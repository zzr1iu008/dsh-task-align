# dsh-task-align 「任务对齐」

DSH Web GUI 插件：**复杂任务开工前，先让它复述"我理解你要的是…"，你点头它才动手。**

> **适用范围：目前仅 native 会话可用。** PTC（代码执行）会话里**卡片可以显示、按钮也可用**，但 `run_code` 必须放行（否则死锁），所以**闸门无法强制拦截**——那种会话里请不要指望它拦住模型。原因见下文「PTC 会话：不支持」。

## 它解决什么

模型对着复杂任务会长时间思考，界面上只有一行「深度求索中，用时 X 秒」——看不出它把你的要求理解成了什么，也看不出它正准备做什么。本插件在动手前插入一道**理解闸门**：复述不清、理解错了，你在第一步就能拦住，而不是等十分钟后拿到一个跑偏的结果。

## 使用

1. 你发出一条任务。**没有内容判定**：不靠长度、关键词或句式去猜"像不像任务"，判据只有一条——模型要不要动工具。
2. 模型调用 `confirm_task_understanding`，给出「我理解你要的是…」+ 3–5 步计划，然后**结束本轮**。
3. 输入框上方出现卡片，三个出口：
   - **确认开工**：闸门打开，模型被唤醒继续执行
   - **改一下**：就地写出订正后的要求，按你写的版本执行
   - **理解错了先别做**：不开工，模型被要求先问清楚
4. 你也可以直接用命令：`/task-align confirm`、`/task-align edit <订正后的要求>`、`/task-align decline`、`/task-align done`。
5. 执行期间模型每步上报进度，摘要行跟着走；收尾后收成一行灰字（带「补充需求」「结束任务」和 `×`）。

## 一道闸门 = 一个任务，不是一次工具调用

| 场景 | 行为 |
|---|---|
| 新任务 | 弹卡片，等你确认 |
| 同一任务的后续轮次 | 模型传 `needsConfirmation: false`，直接放行，不再打扰 |
| 你中途改需求 | 模型传 `isRevision: true`，弹「计划更新」卡片重新对齐 |
| 你没批准就想传 `false` | 被拒绝，仍然弹卡（`false` 不能跳过首次确认） |
| 纯文字回答、不动工具 | 不触发，不打扰 |

摘要行能显示的状态只有四个：`已确认` / `按已批准计划继续` / `已拒绝` / `已取消`（分别对应 `confirmed` / `approved` / `declined` / `aborted`）。

## 闸门是非阻塞的

早期版本让工具**一直等按钮**，导致：卡片只在这通调用进行中存在（你一打字就中止，卡片随之消失），而中止后闸门仍关着，会话被锁死。现在：

| 环节 | 行为 |
|---|---|
| `confirm_task_understanding` | **立即返回** `status: awaiting`，不做任何等待 |
| 闸门 | 保持关闭，除白名单外的工具全部被拒（这就是"暂停"） |
| 卡片 | 从**已结算的结果**（`[task-align:awaiting]`）渲染，随手打字不会让它消失 |
| 你点确认 | 命令开闸 + **唤醒模型**；唤醒消息带 `[task-align]` 前缀，不会被当成新需求再次关闸 |
| 一轮结束（agent idle） | 闸门自动解除，下一条消息重新判定 |

## PTC 会话：卡片支持，拦截不支持

PTC 会话顶层只有 `run_code`，其余工具在程序里调用，子调用记作 `tool/ptc-dispatch`。

- **卡片能显示**：投影同时折叠 `tool/call` 与 `tool/ptc-dispatch`（用 `subCallId` 作调用标识、`arguments` 兼容对象或字符串两种形态），所以 PTC 里的闸门调用同样会得到 `awaiting`，卡片、按钮、命令全部可用。
- **但拦不住**：`run_code` 必须放行，否则"确认工具只能在 run_code 里调"与"run_code 被拦"互相咬死，会话卡死（这个死锁真实发生过）。PTC 里"停下来等你点"靠提示词约束，**不是强制**。
- 因此 PTC 的定位是**展示 + 确认反馈**；**需要真闸门请用 native 会话**。

## 收尾摘要

闸门结算后，输入框上方收成一行灰字：

```
● 任务对齐 · 按已批准计划继续 · 第 2 步进行中 · 1/4 步已完成 · 进行中   [补充需求] [结束任务]  ▸  ×
```

总步数**任何时点都可见**：完成 0 步时显示「共 4 步」，有完成数后显示「1/4 步已完成」，一次都没上报时显示「未上报进度 · 共 4 步」。

点开面板会列出编号的计划条目，圆圈颜色即状态（绿=已完成、蓝=进行中、灰=未开始）：

```
 ①  客户端 summarize 返回每步文本与状态
 ②  展开面板渲染编号步骤清单 + 状态标记 + 样式
 ③  自测渲染并交由你目视确认
```

点开可回看当初确认的那版理解与已上报步数。摘要只读 Chat 快照里的已结算节点，不额外发请求、不写会话日志。

**进度在宿主折叠时就收敛，不留给客户端猜**：

- **后来的步骤覆盖前面**：上报编号更大的步骤时，前面仍是 `doing` 的步骤自动记为完成（模型漏报 `done` 时不会永远挂着"进行中"）
- 客户端只渲染投影里的状态，不再做任何推断

## 进度上报

`update_task_progress`（`step` / `status: doing|done|skipped` / `note`）是可选动作，但**显示完全依赖它**：

- 一次都没上报 → 摘要显示「未上报进度」（这是"没上报"，不是"没干活"）
- 计数按**不同步号**统计，重复上报不会灌水
- 计划基准锁定在"最近一次真正提出计划的调用"（`needsConfirmation: true`），续作调用不会重设计划、也不会让计数归零

## 计划与进度的持久化

计划、步骤状态和批准结果由一个宿主侧 **session projection**（键 `taskAlignPlan`）从会话日志折叠，随投影缓存落盘：

- 重载 / 重启后 `update_task_progress` 仍报得出正确剩余步数（内存丢失时从日志重建）
- 已批准的计划同样可恢复，续作不会因为重载又弹一次卡
- 注册在 `ctx.effect` 里异步完成，**不阻塞插件激活**；失败只损失持久化，闸门照常

## 配置

`cordis.patch.yml` 里本插件的 `config`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 设为 false 等于停用闸门（保留注册） |
| `progressTool` | true | 是否注册 `update_task_progress` |

早期版本有 `timeoutSeconds` / `foregroundMultiplier`（超时自动放行）。非阻塞改造后**已删除**：闸门不占任何调用，没有超时的意义。

## 随包技能

bundle 自带模型可加载的技能 `task-align-plan`（`assets/task-align-enhancer.md`），由独立 Loader 行 `task-align-skills` 提供：复述四要素、可验收步骤五条判据、反模式清单、执行纪律、收尾自检。

技能**不常驻** context，只在系统提示里出现一行标题与描述。`BUNDLED_SKILL_RANK` 写死 600，因为链接安装的目录解析不到 `@deepseek-ai/dsh-skill`。

## 界面

- **输入框上方整行卡片**（`conversation.input.dock`）：闸门等待时出现；确认后收成一行摘要，可点开回看，可 `×` 关闭，换轮自动收起。
- **工具条右侧迷你状态**（`conversation.input.right`）：等待确认 / 第 N 步。不占用语音输入所在的 `activity` 单槽。
- **读写都不走问答接口**：读是 Chat 快照里的工具生命周期，写是一条人类命令。所以关掉审批提示按钮也能生效。
- 几何与配色：列宽公式与「待继续目标」条一致（`100% - 2×side-clearance - 4×dock-inset`，`max-width: card-max-width - 4×inset`）；颜色走宿主主题 token，明暗主题都成立；主按钮用 Okabe–Ito 色盲友好蓝 `#0072B2`（hover `#56B4E9`）。

## 已知限制

1. **PTC 无法硬拦**（见上）。要真拦截就得放弃 PTC 的执行方式。
2. **进度只认模型自报**，不做事后推断；模型不上报就是「未上报进度」。
3. **唤醒依赖 `agent.followup`**：点确认后模型是靠一条合成的用户消息被叫醒的。若该调用失败，闸门已打开但模型不会自动继续——你再发一句即可。
4. 点击确认到状态变化之间，卡片会短暂停在等待态（"你点了按钮"本身不写日志，客户端靠唤醒消息推断）。

## 停止使用

在插件页面关闭本 bundle：闸门、两个工具、系统提示里的规则一起消失；已完成的对话内容不受影响。

会话目录回收（不会进 GUI 列表，可随时搬回）：

```bash
mkdir -p ~/.dsh/session-trash-$(date +%Y%m%d-%H%M%S)
mv ~/.dsh/sessions/--Users-zhangruiliu-deepseek--/session-<id>* ~/.dsh/session-trash-*/
```
