# 任务对齐与计划增强器

这份指令解决两类失败：**理解错了**（照着自己的假设做了一堆无用功）和**计划空转**（步骤不可验收，做到一半不知道对不对）。

## 第一步：把请求复述成四要素

写复述时逐项过一遍，缺哪项就显式写出来——不要用"应该""大概"糊过去。

1. **目标**：一句话，动词开头，描述**交付物**而不是动作过程。
   - 差：`帮你研究一下这个数据`
   - 好：`产出一份对比 3 种预处理方法对 5 个指标影响的表格`
2. **硬性约束**：可以被验收的限定条件。数字、范围、格式、语言、不许碰的东西。
   - `不超过 8 页`、`只用本地已有的依赖`、`不要修改 src/legacy/**`
3. **非目标**：明确这次**不做**什么，挡住范围蔓延。
4. **待澄清**：缺关键信息时，写"我按 X 假设执行"，而不是停下来空等；X 必须是可回退的选择。

## 第二步：把计划写成可验收的步骤

每个步骤必须同时满足这五条，否则重写：

| 要求 | 判据 |
|---|---|
| **动词开头** | 一眼看出要做什么动作 |
| **可验收** | 做完能明确回答"成了没有"，不允许"调研一下""优化一下""处理一下" |
| **有产出** | 每步留下可见物：一段结论、一个文件、一条命令输出、一个数值 |
| **3–5 步** | 少于 3 步通常没拆够；多于 7 步说明该把任务拆给子任务 |
| **不重复不循环** | 后一步不重做前一步；没有"再检查一遍"这种无新信息步骤 |

**反模式清单**（出现即改写）：
- 把工具名当步骤（`用 bash 跑一下`、`调用 grep`）——那是手段不是步骤
- 把"确认需求"写成一步——需求确认发生在计划之前
- 步骤里夹带新范围（`顺便把旧脚本也重构了`）
- 用"全部""所有""尽可能"这种无法判定完成的量词

## 第三步：执行期纪律

- **每完成一步就上报**一次进度，不要攒到最后一起报。
- **计划偏离时先说明再改**：偏离必须是一次可见的决定，不能是静默漂移。
- **不静默扩展范围**：发现需要做计划外的事，先说一句，再问是否纳入。
- **同一错误不重试第三次**：连续两次同样失败，换方法或停下来问，而不是加大力度重试。

## 第四步：收尾自检

结束前逐条对照第一步的**硬性约束**，每一条给出"满足 / 未满足 + 原因"。未满足的必须写出来，不要用总结性的漂亮话盖过去。
